# Как строить сцену: GM3D Studio + GameMaker

Короткое правило: **Studio делает мир, GameMaker делает игру.**
Всё, что видно и стоит в мире (террейн, трава, свет, материалы, расстановка, коллайдеры,
анимации по умолчанию), авторуется в редакторе и уезжает в `scene_gm3d.json`.
Всё, что происходит во времени (ввод, камера, переключение клипов, правила, UI, звук,
сохранения), живёт в GML. Сцена — это контракт между ними.

| Вопрос | Где решается |
|:---|:---|
| Форма холмов, цвет земли, слои, высотная карта | Studio: *Environment & Lighting > Terrain* |
| Трава: форма, цвет, плотность, где растёт | Studio: *Terrain > Procedural Grass & Foliage* |
| Солнце, небо, туман, тени, точечные источники | Studio: *Environment & Lighting > Lighting* |
| Материалы (albedo/normal/roughness), текстуры | Studio: *Materials* |
| Модели, трансформы, иерархия, коллайдеры, клипы | Studio: *Viewport*, *Scene Hierarchy*, *Inspector* |
| Что за объект игрок, как он ходит, куда смотрит камера | GameMaker, GML |
| HUD, меню, звук, сохранения, ИИ, квесты | GameMaker, GML |
| Буфер сущностей, порядок кадра, `update_framework` | GameMaker, GML (обязательный каркас) |

---

## 1. Сборка и запуск

```powershell
.\tools\check.ps1                 # собирает всё (Studio, DLL, тесты) и гоняет CTest
.\build\GM3DStudio.exe --log "$env:TEMP\studio.log"   # запуск редактора с логом
```

`tools\launch_studio.ps1` делает то же самое и печатает лог. Без `--log` release-сборка
молчит: консоли у неё нет.

Полезные режимы без интерфейса:

```powershell
.\build\GM3DCheck.exe scene scenes\meadow.json                  # валидация сцены
.\build\GM3DCheck.exe export scenes\meadow.json C:\tmp\export   # экспорт без редактора
.\build\GM3DStudio.exe --scene scenes\meadow.json --screenshot shot.png --frames 40
.\build\GM3DStudio.exe --scene scenes\meadow.json --simulate 200 --log sim.log
```

`--frames` нужен потому, что террейн и трава строятся не за один кадр: при 30 кадрах
на скриншоте ещё может не быть травы.

## 2. Интерфейс и управление

Панели: **Viewport** (центр), **Scene Hierarchy** (справа сверху), **Inspector**
(справа снизу), **Materials** (там же, вкладкой), **Environment & Lighting** (слева,
вкладки Terrain / Lighting / Assets), статус-бар внизу.

Камера (работает, когда курсор над вьюпортом):

| Действие | Клавиша |
|:---|:---|
| Вращать | ПКМ + мышь |
| Лететь вперёд/назад/вбок | ПКМ + `W`/`S`/`A`/`D` |
| Вверх/вниз | ПКМ + `E`/`Space` вверх, `Q`/`C` вниз |
| Ускорить полёт | `Shift` (×2.5) |
| Приблизиться к точке взгляда | колесо |
| Фокус на выделенном | `F` |
| Выделить | ЛКМ по объекту (или по строке в Hierarchy) |

Редактирование:

| Действие | Клавиша |
|:---|:---|
| Gizmo Move / Rotate / Scale | `W` / `E` / `R` |
| Локальные / мировые оси | кнопка `Local/World` в тулбаре |
| Snap to surface (поставить на землю) | `G` |
| Дублировать / удалить | `Ctrl+D` / `Del` |
| Снять выделение | `Esc` |
| Undo / Redo | `Ctrl+Z` / `Ctrl+Y` |
| Сгруппировать / расгруппировать | `Ctrl+G` / `Ctrl+Shift+G` |
| Play/Stop физики (Jolt) | `P` |
| Сохранить сцену | `Ctrl+S` |

Экспорт в GameMaker **не имеет рабочего хоткея**, хотя меню показывает `Ctrl+E`:
только *File > Export for GameMaker LTS...*.

## 3. Сцена шаг за шагом

### 3.1. Проект (по желанию, но полезно)

*File > New Project...* создаёт `.gm3dproject` — это реестр ассетов и последней сцены,
рядом появляются папки `Assets/` и `Scenes/`. Проект не обязателен, но он запоминает,
что открывать, и держит пути к моделям/текстурам. *File > Open Project...* возвращает
всё как было, включая последнюю сцену.

### 3.2. Террейн

*Environment & Lighting > Terrain*:

1. `Enable terrain` — включить.
2. *Terrain generation*: размер сетки, seed, высота (`m`), размер мира (`m`) →
   `Regenerate terrain...` (спросит подтверждение, потому что стирает скульпт).
3. `Detail scale` — тайлинг фотографического детайла. `0` = плоский цвет слоёв
   (стилизация), `1` = одно фото на 2.5 м (реализм). Для «нарисованного» мира ставь 0.
4. *Material Layers* — четыре слоя: имя, цвет, масштаб текстуры. Кнопка `Paint <слой>`
   включает кисть нужного слоя.
5. Кисти: `Raise`, `Lower`, `Smooth`, `Flatten`, `Paint Layer`, `Grass Brush`; радиус и
   сила — рядом. Рисуешь прямо по террейну во вьюпорте.
6. *Heightmap*: `Import heightmap...` / `Export heightmap...` — grayscale PFM, 32…512 px.

**Ловушка:** если террейн ни разу не красить, сплатмапа нет, и рендер берёт
**процедурную рампу** (зелёная трава, камень на склонах, песок у воды) — твои цвета
слоёв просто не появятся. Хочешь свой цвет — прокрась область (или сгенерируй сцену
скриптом, как `tools\meadow_scene.py`, который пишет сплатмап `255,0,0,0` на всю карту).
Экспорт забирает сплатмап из террейна, так что в GameMaker уедет ровно то, что покрашено.

### 3.3. Трава

*Terrain > Procedural Grass & Foliage*:

- `Enable Grass`, `Grass Color A/B` (тень/солнце);
- `Height`, `Width` — размер лезвия;
- `Max Distance` — дальность отрисовки, `Wind Speed/Strength` — ветер;
- `Snap Grass to Terrain Heights` — поднять/опустить уже нарисованные пучки после
  изменения рельефа;
- `Clear All Grass` — стереть всё и выключить траву.

Два пути, и они по-разному весят:

- **Параметры вместо запекания.** Включить `Enable Grass`, выставить высоту/ширину/
  дальность/цвета и **не** нажимать `Fill Terrain`: при загрузке сцены и при
  `Regenerate terrain...` ковёр строится из `grass_*` полей
  (`build_from_terrain`), а `grass_clumps` остаётся пустым. Сцена и экспорт лёгкие —
  так устроен `scenes/meadow.json`, и в GameMaker загрузчик вызовет `grass_rebuild`
  вместо `grass_load_file`.
- **Запекание.** `Fill Terrain (Procedural)` строит всю траву и сохраняет **каждый**
  экземпляр в `grass_clumps` (на большом мире это сотни тысяч записей: мегабайты JSON
  плюс `grass.bin`). Нужно, только если пучки надо править вручную.
  `Paint Grass Tool` / `Grass Brush` тоже пишет только нарисованные пучки.

### 3.4. Свет и атмосфера

*Lighting*:

- **Sun** — pitch/yaw (направление), цвет, интенсивность;
- **Point lights** — список источников; `+ Add point light`, трансформ в Inspector;
- **Shadows** — включение, 2-каскадная CSM, сила, мягкость, покрытие, качество;
- **Atmosphere** — `sky_color` (он же цвет тумана: купол неба выводится из него),
  начало/конец тумана, ambient.

Небо и дымка связаны: один цвет задаёт и купол, и туман. Хочешь фиолетовый луг —
фиолетовый `sky_color`, и горизонт подхватится.

### 3.5. Материалы

*Materials*: список материалов, albedo/normal/roughness, превью-шар. Фотографические
CC0-наборы лежат в `assets/textures/` (`python tools\fetch_textures.py`), движок сам
находит папку рядом с exe. Материал назначается в Inspector выбранной сущности.

### 3.6. Объекты

- `GameObject > Add Cube/Sphere/Cylinder/Plane/Capsule/Pine Tree/Point Light`;
- `File > Import 3D Model (.glb, .obj)...` или просто перетащи файл в окно;
- в *Scene Hierarchy* — выделение, переименование, вложенность (drag), группы.

Inspector для выбранного:

- **Transform** — позиция/поворот/масштаб (поля + гизмо);
- **Mesh Renderer** — меш, материал, текстура, `Cast Shadow`, `Visible`;
- **Collider & Rigidbody (Jolt)** — тип тела (Static/Dynamic/Kinematic), форма
  коллайдера, показ вайрфреймов;
- **Skeletal Animator** — включить, клип, `Loop`, `Auto-Play`, скорость.

`P` запускает физику: тела падают на террейн и на статические коллайдеры. Это самый
быстрый способ проверить, что объект не висит в воздухе и не проваливается. `P` ещё раз —
стоп, сцена возвращается в исходное состояние.

### 3.7. Проверка перед экспортом

1. `Ctrl+S` — сохранить сцену.
2. `GM3DCheck.exe scene <путь>` — 0 ошибок.
3. `--screenshot` с рабочей камерой (`--camera px,py,pz,tx,ty,tz`) — глазами.
4. `--simulate 200` — численно, где тела остановились (удобно для коллайдеров).
5. `--no-grass` / `--no-shadows` — A/B, если что-то выглядит не так.

### 3.8. Экспорт

*File > Export for GameMaker LTS...* → выбрать папку. Экспорт пишет:

```
scene_gm3d.json        сцена: окружение, террейн (высоты, сплатмап, слои), сущности
scr_gm3d_load_scene.gml загрузчик для GameMaker (создаёт объекты, коллайдеры, анимации)
terrain.pfm            высотная карта (если есть террейн)
grass.bin              запечённая трава (только если clumps не пустые)
assets\<...>           модели и текстуры, на которые ссылается сцена
```

Папка может уже содержать эти файлы — экспортёр спросит и заменит их. Ничего, кроме
этих файлов, он не трогает.

## 4. Что делать в GameMaker

### 4.1. Каркас проекта (один раз)

В `MeadowDemo` это уже сделано, повторяй как шаблон:

1. **Расширение `GM3Dext`**: `extensions\GM3Dext\GM3Dext.dll` + `GM3Dext.yy`.
   `.yy` — таблица экспортов (имя, число аргументов, типы). **Новая нативная функция
   появляется в GML только после правки этой таблицы**, иначе «unknown function».
   После каждой пересборки движка копируй свежий `build\GM3Dext.dll` в расширение.
2. **Скрипт `scr_gm3d`** — GML SDK из `gml_example\scr_gm3d.gml`. Копия обязана
   совпадать с `3DTEST\scripts\scr_gm3d\scr_gm3d.gml` (`tools\sync_gml_sdk.ps1 -Check`
   проверяет это в `check.ps1`); в `MeadowDemo` её обновляй руками.
3. **Скрипт `scr_gm3d_load_scene`** — из экспорта, целиком.
4. **Объект `obj_3d_entity`** — «носитель» сущности; загрузчик создаёт его экземпляры.
5. **Included Files**: положи экспорт в `MeadowDemo\datafiles\` и зарегистрируй в IDE
   (Scene → Included Files): `scene_gm3d.json`, `terrain.pfm`, `grass.bin` если есть,
   и `assets\*.glb`. Подпапки поддерживаются: `assets/UAL1_Standard.glb` доедет до
   `<игра>\assets\UAL1_Standard.glb`.
6. **Объект-контроллер** в стартовой комнате: загрузка сцены в `Create`, буфер и
   `update_framework` в `Step`.

### 4.2. Обязательный минимум в контроллере

```gml
// Create
gm3d_init(5000);
scene = gm3d_load_scene_json("scene_gm3d.json");   // путь относительно datafiles

// Step — каждый кадр
var _dt = delta_time / 1000000.0;

gm3d_camera_set(cam_px, cam_py, cam_pz, cam_tx, cam_ty, cam_tz, 60.0);

// сущности: 64-байтные записи в общий буфер (см. obj_meadow\Step_0.gml — копируй блок)
var _buff = global.gm3d_buffer;
buffer_poke(_buff, 8, buffer_u32, instance_number(obj_3d_entity));
var _idx = 0;
with (obj_3d_entity) {
    buffer_seek(_buff, buffer_seek_start, GM3D_HEADER_SIZE + _idx * GM3D_ENTITY_SIZE);
    // x,y,z, qx..qw, scale x3, id, mesh_id, material_id, flags, physics_body_id, param1, param2
    _idx++;
}

update_framework(_dt);   // без этого окно чёрное, хотя мост и логи живы
```

Три вещи, без которых не работает ничего:

- **`update_framework` каждый кадр** — иначе движок не рисует кадр вообще;
- **запись буфера** — иначе будут террейн и трава, но ни одного объекта;
- **свежий DLL** в расширении — старый бинарник даёт чёрное окно без ошибок.

### 4.3. Геймплей — уже только здесь

Экспортированная сцена даёт мир и сущности; дальше в GML:

- камера (третье лицо, орбита, зум), ввод, стрейф/бег/прыжок;
- переключение клипов (`gm3d_anim_play`), скорость, состояния;
- высота под ногами — `gm3d_terrain_get_height(x, z)`;
- HUD, меню, звук, сохранения, правила.

Живой пример всего этого — `MeadowDemo\objects\obj_meadow` (Create + Step).

## 5. Симптом → причина

| Симптом | Причина |
|:---|:---|
| Чёрное окно, мост живой | не вызывается `update_framework` |
| Террейн и трава есть, объектов нет | не пишется буфер сущностей |
| «Unknown function» в GML | функция не добавлена в `GM3Dext.yy` или DLL старый |
| Террейн зелёный, хотя слои фиолетовые | нет сплатмапа: террейн не покрашен |
| Материалы серые/процедурные | нет `assets/textures` рядом с exe или в рабочей папке |
| Модель не загрузилась | файл не попал в `datafiles` (или не зарегистрирован) |
| Персонаж есть, но не двигается | камера/ввод в GML, сцена тут ни при чём |
| Сцена «не та», что в редакторе | экспорт не пересобран/не скопирован в `datafiles` |

## 6. Скриптовый путь (когда сцена большая)

Сцену можно не кликать, а генерировать: `tools\meadow_scene.py` пишет JSON напрямую
(холмы, слои, сплатмап, трава, персонаж) и печатает готовую строку камеры. Это удобно
для повторяемых миров и для диффов в git, но формат надо соблюдать — проще начать с
редактора, сохранить сцену и посмотреть, как выглядит JSON.
